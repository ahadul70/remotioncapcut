## 2. Track data model

Implement or refine a centralized track model with:
- Stable track IDs.
- Track type: video or audio.
- Track name and ordering.
- Locked state.
- Visible state for video tracks.
- Muted state for audio tracks.

Reuse existing structures where possible. Avoid duplicating editing state or creating a parallel timeline model.

Existing clips must reference valid tracks. Preserve stable clip IDs, integer-frame timing, source in/out points, and imported media references.

## 3. Timeline interaction

- Add video/audio tracks.
- Move clips horizontally and between compatible tracks.

- Prevent edits to locked tracks.
- Prevent audio-only media from being placed on video tracks and video-only media from being placed on audio tracks, unless the existing architecture explicitly supports a different behavior.

Do not implement ripple editing or complex collision resolution unless the existing architecture already supports it reliably. Overlapping clips should follow a documented and consistent behavior.
