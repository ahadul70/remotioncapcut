# 4. Visual Design System

## Overall aesthetic

Create a sophisticated dark interface with a neutral charcoal background, subtle borders, compact controls, restrained accent colors, and excellent visual hierarchy.

The editor should feel precise and professional without looking intimidating.

### Color palette

Use these as starting design tokens:

- Main application background: `#111214`
- Panel background: `#18191D`
- Elevated panel background: `#202126`
- Hover background: `#292B31`
- Active/selected background: `#30333B`
- Primary text: `#F3F4F6`
- Secondary text: `#A1A4AE`
- Muted text: `#717581`
- Borders and separators: `#303238`
- Primary accent: `#8B7CFF`
- Accent hover: `#A196FF`
- Success: `#55C995`
- Warning: `#E9B86A`
- Destructive action: `#F06C75`

Use the accent color sparingly for selections, active tools, playhead highlights, and primary actions.

Do not make the entire application purple. Most of the interface should remain neutral and dark.

Use readable contrast. Timeline clips should have distinct colors by media type or track, but colors must remain muted enough to avoid visual clutter.

### Typography

Use a clean interface font such as Inter if already available. Otherwise, use a suitable system sans-serif font.

Typography guidelines:

- Application title: 14–16 px.
- Main section labels: 12–14 px.
- Standard controls: 12–13 px.
- Secondary metadata: 10–12 px.
- Important timecodes: use tabular numerals.
- Avoid oversized headings inside the editing workspace.

### Spacing and shapes

- Use a consistent 4 px spacing scale.
- Use 6–9 px corner radii for controls and panels.
- Prefer thin separators over heavy borders.
- Keep toolbars compact.
- Use subtle hover transitions of approximately 100–180 ms.
- Avoid excessive shadows, gradients, glassmorphism, and decorative effects.
- Use consistent icon sizing, generally 14–18 px.

Use an existing icon library if one is installed. If not, choose a lightweight, consistent icon solution only if necessary. Avoid mixing emoji, text symbols, and unrelated icon styles.

Every icon-only button should have a tooltip and an accessible label.

## 10.3 Time ruler

For example:

- At a closer zoom, show markers every 1 second.
- At a very close zoom, show frame divisions where practical.

Implement a consistent timeline coordinate model.

Maintain a defined relationship between:

- Timeline frame.
- Timeline time in seconds.
- Horizontal pixel position.
- Current zoom level.

Use the project's frame rate as the source of truth.

Do not hardcode a conversion that only works at 30 fps without consulting the actual composition settings.

For example, the timeline's pixel position should be calculated from the timeline frame and the current pixels-per-second or pixels-per-frame scale.

Use one consistent coordinate system across:

- Clip placement.
- Playhead position.
- Ruler markers.
- Dragging.
- Splitting.
- Seeking.
- Zooming.

# 11. Editing State Architecture

Create a real application state model rather than storing editing information only in UI components.

The editor should eventually support an editing structure similar to this:

```ts
type Clip = {
  id: string;
  assetId: string;
  name: string;
  type: "video" | "audio" | "image" | "text";
  trackId: string;

  // All timeline positions and durations use integer frames.
  timelineStartFrame: number;
  sourceStartFrame: number;
  durationInFrames: number;

  // Optional properties for future editing features.
  playbackRate?: number;
  volume?: number;
  opacity?: number;
};

type Track = {
  id: string;
  type: "video" | "audio";
  name: string;
  muted?: boolean;
  locked?: boolean;
  visible?: boolean;
};

type EditorState = {
  clips: Clip[];
  tracks: Track[];
  selectedClipId: string | null;
  playheadFrame: number;
  zoom: number;
  snappingEnabled: boolean;
};
```

Adapt the schema to the existing project when necessary. Do not create duplicate sources of truth.

Use unique IDs for clips. Never use the array index as the identity of a clip.

Use integer frames for timeline positions and durations wherever possible. Convert to seconds and pixels only when displaying or rendering the timeline.

Keep the editing model independent from the UI layout.

The same editing state should drive:

- The timeline.
- The preview.
- The inspector.
- The playhead.
- Undo and redo.
- Eventually, the export composition.

Use a clear component structure and avoid putting the entire application into one enormous React component.
